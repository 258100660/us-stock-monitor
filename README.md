# 四、具体策略

**1. 策略一：大单监测 (Large Order Monitoring)**

- **功能细化**:

  - **监控目标**: 持续扫描所有股票的Level 1 Bid Size 和 Ask Size。

  - **触发逻辑**: 这是一个 **“或”** 逻辑。只要 Bid Size **或者** Ask Size 任一者超过用户设定的股数阈值，并且该股票的当前价格在用户设定的价格区间内，该股票就会被捕获并显示在结果列表中。

- **用户可配置参数**:

  - **价格区间**: 下拉框，提供多个预设或可自定义的价格区间，\
    \$0.5-\$5\
    \$5.01-\$10\
    \$10.01-\$20\
    \$20.01-\$40\
    \$40.01-\$60\
    \$60.01-\$100\
    \$100.01-\$200\
    \$200.01-\$1000

  - **订单股数阈值**: 下拉框20 50 100 300 500 1000 2000 5000 10000 20000 50000手。

- **结果显示内容**:

  - 股票代码 (Symbol)

  - 触发时价格 (Price)

  - 触发时间 (Time) - 精确到秒。

  - 补充：如果时间段内出现超过3次，最多显示3次他的价格、触发时间。 并且显示是卖(红色)、还是买(绿色)。如果持续出现信号，用最新的价格、和时间覆盖（保留最多3笔买、或者3笔卖）。（交易员可以用开关关闭这个效果）

  - 如果出现超级买单、超级卖单，则高亮显示。添加一个输入条件，设置最大单的数量。 那么，》=下拉框选中的股数，并且 \<= 最大单数量，就普通显示；如果\> 最大单数量，就高亮显示。如果未输入【最大单数量】，不做高亮处理。（交易员可以用开关关闭这个效果）

**2. 策略二：买卖单比例监测 (Bid/Ask Ratio Monitoring)**

- **功能细化**:

  - **核心计算**:

    1.  获取指定股票的 Bid Size 和 Ask Size。

    2.  比较两者大小，将**数值较大者作为分子**，**数值较小者作为分母**，进行除法运算得出比例。

    3.  例如，Bid Size为10000股，Ask Size为30000股，则比例为 30000 / 10000 = 3。

  - **关键前置条件 - 价差过滤 (Spread Filter)**:

    - 在进行比例计算前，必须先检查 Ask Price 与 Bid Price 的差值。

    - **只有当 Ask Price - Bid Price \<= \$0.01 时**，该股票才进入比例监测流程。如果价差大于0.01（例如，Bid为10.00，Ask为\$10.02），则直接忽略该股票，不进行计算和显示。

  - **触发逻辑**: 当通过价差过滤的股票，其计算出的买卖单比例 **≥** 用户设定的比例阈值时，触发显示。

- **用户可配置参数**:

  - **价格区间**: 下拉框，提供多个预设或可自定义的价格区间，\
    \$0.5-\$5\
    \$5.01-\$10\
    \$10.01-\$20\
    \$20.01-\$40\
    \$40.01-\$60\
    \$60.01-\$100\
    \$100.01-\$200\
    \$200.01-\$1000

  - **比例阈值**:下拉选择，如 1, 3, 5, 10, 20, 50, 100。

- **结果显示内容**:

  - 股票代码 (Symbol)

  - 触发时价格 (Price)

  - 触发时间 (Time)

  - 添加一个下拉框：最大比例（200，300，500）；跟策略1类似，正常区间显示显示；超过这一比值时，高亮显示。（交易员可以用开关关闭这个效果）

新策略：

买卖单的比值：在设定的买卖单比值上， 如果比值不小于原来的值、并且价格在3次比对中，一次次变高或变低，则股票闪烁。（价格用bid或ask都行）

**3. 策略三：持续横盘/盘整监控 (Consolidation/Sideways Movement Monitoring)**

- **功能细化**:

  - **核心逻辑**: 监测价格在一段时间内是否“未发生显著变化”。

  - **基准时间点管理 (Crucial Logic)**: 这是该策略最核心的部分。

    1.  系统为每支股票维护一个“基准时间点”和对应的“基准价格”（使用Bid价）。

    2.  初始基准点是程序开始监控的时间点（如开盘9:30）。

    3.  系统持续获取新价格。如果新价格相比“基准价格”的**变动超过了\$0.01**，则**立即废弃旧的基准点**，将当前时间点和价格设为**新的基准点**。

    4.  如果价格变动未超过\$0.01，则基准点保持不变。

  - **触发逻辑**:

    1.  系统定时（例如每秒）检查当前时间与“基准时间点”的时间差。

    2.  如果这个时间差达到了用户设定的时间周期（如5分钟），并且在此期间基准点从未被重置过（即价格始终在\$0.01范围内波动），则触发，将该股票列为横盘股。

  - **数据需求**: 需要为市场上约4000支股票在内存中维护各自的基准时间和价格，并持续更新。

- **用户可配置参数**:

  - **价格区间**: 下拉框，提供多个预设或可自定义的价格区间，\
    \$0.5-\$5\
    \$5.01-\$10\
    \$10.01-\$20\
    \$20.01-\$40\
    \$40.01-\$60\
    \$60.01-\$100\
    \$100.01-\$200\
    \$200.01-\$1000

  - **时间周期**: 下拉选择 1分钟, 5分钟, 10分钟, 15分钟, 30分钟 (每个时间窗口都要计算)

- **结果显示内容**:

  - 股票代码 (Symbol)

**4. 策略四：短期波动监控 (Short-Term Volatility Monitoring)**

- **功能细化**:

  - **核心逻辑**: 采用**滚动时间窗口 (Rolling Time Window)** 的方式计算价格波动率。

  - **计算方法**:

    1.  以当前时间 T 为终点，用户设定的时间窗口 W（如5分钟）为时长，确定一个监测区间 \[T-W, T\]。

> 2\. 盘中直接使用change %，这个值。按最大% - 最小%

- **触发逻辑**: 当计算出的波动率 **≥** 用户设定的百分比阈值时，触发显示。

- **用户可配置参数**:

  - **价格区间**: 下拉框，提供多个预设或可自定义的价格区间，\
    \$0.5-\$5\
    \$5.01-\$10\
    \$10.01-\$20\
    \$20.01-\$40\
    \$40.01-\$60\
    \$60.01-\$100\
    \$100.01-\$200\
    \$200.01-\$1000

  - **时间窗口**: 下拉选择 5分钟, 10分钟, 20分钟，30分钟 (每个时间窗口都要计算)。

  - **波动幅度阈值**: 下拉选择 1%, 3%, 5%, 10%, 20%。

- **计算公式**: 第5分钟的change% - 第0分钟的； 第6分钟的change% - 第1分钟的；

- **结果显示内容**:

  - 股票代码 (Symbol)

**5. 策略五：异常波动监控 (Abnormal Volatility Monitoring)**

- **功能细化**:

  - **核心逻辑**: 捕捉秒级的、非连续性的价格剧烈跳动。

  - **触发机制 - “四次数据比对法”**:

    1.  系统为每支股票建立一个数据队列，持续接收高频价格更新（Ticks）。

    2.  当收到第1个价格更新时，记录其价格 P1。

    3.  忽略第2、第3次更新。

    4.  当收到第4个价格更新时，记录其价格 P4。

    5.  计算波动率 = (\|P4 - P1\| / P1) \* 100%。

    6.  如果波动率 **≥** 用户设定的阈值，则触发显示。

    7.  盘中用 change%来算

    9.  盘后以last 报价为基准（小数点后如果有多位数，直接截取到小数点后两位，不做四舍五入），每次现价与last的比值为百分比，拿后一次的百分比减前一次的，就是这两次的波动

    10. 盘前以close为基准（小数点后如果有多位数，直接截取到小数点后两位，不做四舍五入）。每次现价与close的比值为百分比，拿后一次的百分比减前一次的，就是这两次的波动

    11. 盘中是现价/昨天收盘

- **用户可配置参数**:

  - **价格区间**: 下拉框，提供多个预设或可自定义的价格区间，\
    \$0.5-\$5\
    \$5.01-\$10\
    \$10.01-\$20\
    \$20.01-\$40\
    \$40.01-\$60\
    \$60.01-\$100\
    \$100.01-\$200\
    \$200.01-\$1000

  - **波动幅度阈值**: 下拉选择 5%, 10%, 20%。

- **结果显示内容**:

  - 股票代码 (Symbol)

**6. 全局功能与设定 - 深度细化**

- **盘前/盘后交易模式**:

  - **自动切换逻辑**:

    - 主程序在设置的夏令时或冬令时的时间点，自动切换盘前/盘中/盘后。

> 只负责取数据和计算、不同的策略是不同的交易员的客户端上设置的。

- **多重条件高亮**:

  - 如果某股票符合多个策略， 则在每一个策略中不显示，合并显示到多重条件的列表里。并用显示它具体满足策略几（比如：1、2、3）

  - **状态维护**: 系统需要在后台维护一个全局的、按股票代码组织的触发状态列表，以判断哪些股票满足高亮条件。

- **显示与屏蔽机制**:

> 股票显示时长有5 10 30分钟可选，超过所选时长自动消失。如果时间段内再次出现该股票信号，则他需要重新计时，等计时点到了信号列表中隐藏该股票。

- **手动屏蔽**: 在结果列表的每一行股票旁，应提供一个屏蔽按钮或右键菜单选项，点击后弹出屏蔽时长选项（1小时、3小时、当天）。被屏蔽的股票在指定时间内将不再出现在任何结果列表中，即使它满足触发条件。
